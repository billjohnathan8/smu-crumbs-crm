# PostgreSQL Helm Warnings - Resolution Summary

**Date**: February 7, 2026  
**Issue**: Helm warnings during local K8s deployment  
**Status**: ✅ Resolved

## Warnings Encountered

During `make build-and-deploy-local` execution, the following warnings appeared when deploying Bitnami PostgreSQL:

1. ⚠️ **SECURITY WARNING**: Original containers have been substituted
2. ⚠️ **PASSWORD WARNING**: Password will be ignored on new installation with previous PVC
3. ⚠️ **ROLLING TAG WARNING**: `bitnami/postgresql:latest` detected
4. ⚠️ **ROLLING TAG WARNING**: `bitnami/os-shell:latest` detected  
5. ⚠️ **RESOURCES WARNING**: Resources sections not set

## Root Causes

All warnings originated from an incomplete Helm values configuration in:
- **File**: `platform/k8s/infra/helm-values/postgresql-values.yaml`
- **Problem**: Minimal configuration with only auth and persistence settings
- **Impact**: Insecure defaults, non-reproducible deployments, unbounded resource usage

## Production Considerations

🚨 **IMPORTANT**: The current configuration is suitable for **local development only**.

For production environments, additional changes are required:

1. **Never use plaintext passwords**:
   ```yaml
   auth:
     existingSecret: "postgres-credentials"  # Reference Kubernetes Secret
   ```

2. **Enable persistence**:
   ```yaml
   primary:
     persistence:
       enabled: true
       size: 100Gi
       storageClass: "your-storage-class"
   ```

3. **Increase resources**:
   ```yaml
   primary:
     resources:
       limits:
         cpu: 2000m
         memory: 4Gi
       requests:
         cpu: 1000m
         memory: 2Gi
   ```

4. **Enable high availability**:
   ```yaml
   architecture: replication
   replication:
     enabled: true
   ```

5. **Pin to digest-based images** (even more secure than tags):
   ```yaml
   image:
     tag: "17.2.0-debian-12-r10@sha256:abcd1234..."
   ```

## Questions & Answers

**Q: Why did we set an explicit password for local dev?**  
A: Prevents password mismatches when recreating the cluster and makes debugging easier. Production should use Kubernetes Secrets.

**Q: Can I update the PostgreSQL version?**  
A: Yes! Check [Docker Hub](https://hub.docker.com/r/bitnami/postgresql/tags) for available tags and update `image.tag` in `postgresql-values.yaml`.

**Q: Will this affect my running cluster?**  
A: The next deployment will use the new configuration. If your cluster is already running, it will be torn down and recreated as part of your build-and-deploy pipeline.

**Q: Why 500m CPU and 512Mi memory?**  
A: Conservative limits suitable for local dev. Adjust based on your workload and machine resources.
